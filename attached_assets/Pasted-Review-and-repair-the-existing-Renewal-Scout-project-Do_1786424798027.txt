Review and repair the existing Renewal Scout project. Do not replace it with a new architecture and do not remove working features. Make the following changes in the existing Node/Express, React, Drizzle and PostgreSQL project.

SAFETY BOUNDARY

Renewal Scout may collect requirements, monitor renewal dates, extract current-deal information, search public offers, compare them and prepare a checklist. It must never:

- Log in to a supplier, bank, insurer or comparison account.
- Submit an application, quotation form or credit search.
- Accept terms, cancel or switch a service.
- Make a payment or financial transaction.
- Describe an offer as “best” unless eligibility, availability, features and total cost are all verifiably comparable.
- Recommend cancelling life insurance before replacement cover is active.

Keep this boundary enforced in application code, tests and static user-facing warnings.

Allow Drizzle’s migration journal to operate normally.

Add a new reconciliation migration that safely upgrades databases previously created with "drizzle-kit push". It must use appropriate "ALTER TABLE ... ADD COLUMN IF NOT EXISTS" statements and conditionally create every required foreign key, unique constraint, check constraint and index.

Add database constraints for:

3. STRICT SHARED VALIDATION

Create shared versioned Zod schemas used by both API routes and the React forms.

Do not use "Boolean(value)", loose "Number(value)" conversion, arbitrary JSON records, or unchecked "unknown" values.

Validation must:

- Require finite numbers.
- Require integers where appropriate.
- Enforce sensible minimums and maximums.
- Validate real "YYYY-MM-DD" calendar dates.
- Validate and normalize UK postcodes.
- Enforce string and array length limits.
- Validate service type enums.
- Reject unknown keys with a clear 400 response rather than silently discarding them.
- Validate positive safe-integer route IDs; "1abc", zero and negative IDs must be rejected.

7. DOCUMENT EXTRACTION

Keep documents in memory only and never intentionally persist the original bytes.

Require successful magic-byte detection. If "fileTypeFromBuffer" cannot identify the file, reject it. Never fall back to the browser-provided MIME type.

Require PDF, JPEG or PNG; enforce the size limit; add upload/extraction rate limiting; use a generic filename in the OpenAI request; and add an OpenAI request timeout and controlled retry policy.

Add "store: false" to extraction requests.

Correct the disclosure to say:

“Renewal Scout does not intentionally save the original document. It is transmitted to OpenAI for extraction. OpenAI retention depends on your API organisation’s data-control settings. Redact account numbers, payment details, full addresses and unrelated personal information before upload.”

Require an unticked consent checkbox before upload.

Persist only the validated extracted draft values and metadata, never original bytes. Add a draft status with "draft", "applying", "applied", "discarded", "expired" and "failed". Add expiry and a real discard endpoint so clicking Discard updates the database.

Allow a user to resume a pending extraction after refreshing the page.

Confirmation must be atomic:

- Start a database transaction.
- Conditionally change the extraction from "draft" to "applying".
- If no row was changed, return 409.
- Validate every accepted value against the service-specific schema.
- Upsert the current deal.
- Mark the extraction "applied".
- Commit all changes together.

Two concurrent confirmations of the same extraction must result in exactly one success and one 409.

Calculate estimated savings in server code only when the current cost and proposed cost are genuinely comparable. Include setup charges, discounts, price increases and total contract cost. If a personalised quotation is required, savings must be null.

9. RESEARCH JOBS AND SCHEDULING

Do not execute important jobs solely with fire-and-forget promises in an HTTP request.

Implement a PostgreSQL-backed worker loop:

- Scheduler only inserts due jobs.
- Worker polls queued jobs.
- Jobs are claimed atomically.
- Use lease/heartbeat timestamps so genuinely abandoned jobs can be recovered.
- Retries must be bounded.
- Multiple processes must not execute the same run.

Start the scheduler and worker only in "src/index.ts", after migrations and database readiness. Importing "app.ts" must have no scheduler, signal-handler or background-job side effects.

Parse "SCHEDULER_ENABLED" strictly. Only case-insensitive ""true"" should enable it. Validate scheduler hour, minute and timezone.

Fix the expired-renewal loop:

- If the target date is in the past, "needsResearch" must return false.
- Always set "nextResearchAt" to either the calculated date or null.
- Do not leave an old due date in place after research.
- Update the completed run and service schedule transactionally.
